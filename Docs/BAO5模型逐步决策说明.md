# BAO5 模型逐步决策说明

本文面向不阅读源码的使用者，按模型实际执行顺序说明：数据如何变成单人预测分、单人分如何变成五人阵容、赛后数据怎样回到后续决策。这里记录的是当前实现；模型没有拿到的数据不会被假设成已知。

## 先看一眼：完整决策链

```text
登录 BAO5 并读取球员库、赛程
  ↓
确定未来最多 7 个有效比赛日及每一天参赛球队
  ↓
只留下当天参赛球队的有效球员
  ↓
基础 Fantasy 分
  ↓
近期 / 历史对阵 / 对位 / 盘口 / 伤病 / 替补机会 / 前五偏好修正
  ↓
季前赛折扣 × 赛后总体校准系数
  ↓
剔除高风险球员
  ↓
动态规划搜索 2前3后 与 3前2后阵容
  ↓
在 5 人、能量 ≤150 的约束内选预测总分最高的一组
  ↓
展示建议；只有独立提交动作才会写入 BAO5
  ↓
赛后回填结果、记录误差、累计前五选人反馈
```

## 1. 先确定“哪一天、哪些人可以被考虑”

1. 从 BAO5 读取当前球员库和比赛赛程。球员的能量、位置、场均数据以 BAO5 球员库为准。
2. 过滤掉已经结束的比赛，并按未来比赛日期排序。网页最多展示未来 7 个比赛日。
3. 若未来赛程中有季前赛，当前窗口只取与最近阶段相符的比赛，不把季前赛和常规赛混在同一批预测里。
4. 对每个比赛日，收集当天所有比赛的主客队；球员必须属于其中一队且 `active` 不是 `false`，才能进入候选池。
5. 同一球员一天只参与其所属球队当天那场比赛的对手、赔率和对位计算。

如果当天没有可用比赛，或者候选人数不足以组成合法阵容，模型会返回空阵容，而不是补入当天不参赛的球员。

## 2. 先算球员的基础 Fantasy 分

游戏计分公式为：

```text
基础分 = 得分 + 1.2 × 篮板 + 1.5 × 助攻 + 3 × 抢断 + 3 × 盖帽 − 失误
```

球员库中的技术统计是场均口径。实现会先用这组场均统计换算当前 Fantasy 分；如果这项计算不为正，则退回 BAO5 提供的 `average`。

基础分随后按出场场次做可信度折扣：

```text
可信度 = min(已出场场数 / 20, 1)
基础预测 = 换算分 × (0.5 + 0.5 × 可信度)
```

直观例子：

- 0 场样本时，乘数是 0.5；
- 10 场样本时，乘数是 0.75；
- 20 场及以上时，乘数是 1。

这一步降低新赛季少量样本被直接当成稳定能力的风险。注意：它不是“向联盟平均值收缩”；当前公式是对换算分乘可信度系数。

## 3. 然后逐项修正预测分

对一个球员，完整计算可以概括为：

```text
个人预测分 =（基础预测与可用近期/历史信号的加权结果）
           × 对位系数
           × 盘口系数
           × 伤病系数
           × 替补机会系数
           × 前五偏好系数
           × 赛季阶段系数
           × 总体校准系数
```

缺失的数据一般令对应系数回到 1，或让对应信号不参与混合。下面按代码执行含义逐项说明。

### 3.1 近期状态

如果 BAO5 球员数据含有效的 `recentAverage`，模型会将它与基础预测混合：

```text
近期混合分 = 基础预测 × (1 − 有效近期/历史权重之和)
           + 近期平均分 × 近期权重
           + 历史对阵信号 × 历史权重
```

只有实际存在的信号才参与。某个信号缺失时，它的权重不会占住混合份额；剩余份额回到基础预测。

BAO5 当前不一定提供 `recentAverage`。字段缺失时，模型不自行抓取或生成最近 5 场/10 场数据，近期信号直接跳过。

### 3.2 历史对阵

模型查找本地 `data/history-player/output/` 中该球员对不同球队的历史记录，并计算：

```text
历史信号 = (对该对手的平均表现 − 对所有对手的平均表现)
           / max(1, 对所有对手的平均表现)
```

相对差异限制在 −20% 到 +20%。没有对手、文件、有效比赛或对手样本时，历史信号缺失，不参与加权混合。

限制：这组文件的历史统计口径未必与 BAO5 Fantasy 分完全一致，所以历史信号只当相对方向参考，不是精确的 BAO5 得分预测。

### 3.3 对位修正

模型根据球员位置映射到防守位置：`C→C`、`G→PG`、`F→SF`；未识别时按 BAO5 的前后场映射到 `PF` 或 `PG`。随后查找对手该位置的 `PTS_Rank`。

```text
对位系数 = 限幅(1 + (PTS_Rank − 75) / 75 × matchup权重,
                 1 − matchup权重,
                 1 + matchup权重)
```

代码直接把源数据的 `PTS_Rank` 数值代入。对位行找不到时系数为 1。该信号不会改变阵型，只会改变该球员的预测分和排序。

### 3.4 盘口总分

赔率数据中优先读取 Pinnacle 主盘的比赛总分；不把球员个人大小分盘口用作这一步。

```text
盘口系数 = 限幅(1 + (比赛总分 − 220) / 220 × 赔率权重 × 2,
                 1 − 赔率权重,
                 1 + 赔率权重)
```

没有可用总分时系数为 1。让分目前用于页面展示，不直接进入个人预测公式。赔率刷新由数据采集策略控制，并非每次页面刷新都重新请求赔率服务。

### 3.5 伤病状态与出场概率

优先按球员 ID 查伤病状态。状态概率取值顺序如下：

1. 如果来源给了数值或百分数字符串，解析为 0 到 1；
2. 否则使用映射：`available 97%`、`probable 85%`、`questionable 55%`、`doubtful 25%`、`out 0%`；
3. 无法识别的状态默认 75%。

聚合伤病没有当日官方报告支撑时，会向“可出场”方向折算风险：

```text
折算概率 = 1 − (1 − 来源概率) × 0.55
```

当球员存在伤病条目时：

```text
伤病系数 = max(0, 1 − (1 − 折算概率) × injury权重)
```

若没有伤病条目，伤病系数为 1。代码虽然为无条目球员计算了 97% 默认概率，但当前该概率不会再乘进预测分。

另有硬排除规则：状态键为 `out`、`doubtful`、`questionable`，或标签包含“缺阵、出战成疑、存疑、赛前决定”等文字时，球员不进入最终阵容优化池。也就是说，部分“存疑”状态不只是降分，而是直接禁选；数据来源和状态键会影响触发结果。

官方伤病数据只有在 `available=true` 且报告日期不早于比赛日时，才被视作该日官方报告可用。聚合来源与官方来源会在球员理由中区分。

### 3.6 队友缺阵带来的替补机会

如果同队受限名单中有 `out`、`doubtful` 或 `questionable` 球员，且缺阵者与候选人有相同原始位置，模型再检查候选人是否处于同位置深度排序的前三名。

符合时：

```text
替补机会系数 = 1 + min(0.18, replacement权重)
```

否则系数为 1。该规则是有限的角色加成，不会预测具体分钟、触球率或使用率。

### 3.7 前五阵容选人反馈

模型会读取已经公开的日榜前五名阵容与逐人得分，累计每名球员的：入选次数、每次平均得分、入选率。只使用已经公开且成功读取的阵容。

对每名有历史样本的球员，先计算：

```text
表现差异 = 限幅((球员平均得分 − 有样本球员的平均得分基线) / 基线, −1, +1)
人气信号 = 限幅((入选率 − 0.2) × 2 + 表现差异 × 0.35, −1, +1)
前五偏好系数 = 1 + 人气信号 × crowd权重
```

因此，常被前五选择且实际得分相对较高的球员可能轻微加分；单纯热门但表现较差的球员也不保证加分。没有累计样本时，人气信号为 0、系数为 1。

### 3.8 季前赛折扣

季前赛统一乘以 `0.84`，相当于预留 16% 的轮换不确定性折扣。常规赛乘以 1。它对同日所有候选人都会生效，因此通常改变绝对预测分，而不改变同日球员之间的相对顺序；但会影响预测和实际分数的整体校准。

### 3.9 总体赛后校准

服务端从已完成且同时有预测值、实际值的历史记录中计算：

```text
总体校准系数 = 限幅(所有实际总分之和 / 所有预测总分之和, 0.85, 1.15)
```

没有可用历史样本，或预测分总和不为正时，系数为 1。它按累计总分比计算，不是最近 N 天滚动回归，也不是逐球员参数。

## 4. 权重模式究竟是什么意思

代码里的权重有两种性质：近期/历史权重用于基础分与信号的混合；对位、赔率、人气权重用于修正系数；伤病与替补权重又分别控制风险和机会。因此不要把五个界面数字理解为统计学意义上的五个互斥概率。

### 内置模式参数

| 参数 | 偏低风险 | 高风险 | 用在哪里 |
| --- | ---: | ---: | --- |
| 近期 | 18% | 42% | 基础分与近期均值的混合 |
| 历史对阵 | 8% | 24% | 基础分与历史信号的混合 |
| 位置对位 | 8% | 12% | 对位系数 |
| 赔率 | 4% | 8% | 总分盘口系数 |
| 伤病 | 1.25 | 1.00 | 有伤病条目时的风险惩罚 |
| 替补机会 | 0.14 | 0.28 | 符合规则时的加成，上限 18% |
| 前五选人 | 4% | 8% | 前五偏好系数 |

### 自定义权重

页面允许五项信号独立拖动，但单项最大值受“其它四项当前数值”约束，所以五项合计**不得超过 100%**，不要求刚好等于 100%。拖动一项时，其它四项保持不变；当前项最多只能到 `100% − 其它四项之和`。例如前四项合计 95%，最后一项最多 5%。

自定义输入只替换上述五项：近期、历史、对位、赔率、人气。伤病与替补权重仍沿用所选模式对应的值。服务端不偷偷归一化或重新分配比例；超过总和上限的请求会被拒绝。

## 5. 五人阵容如何被选出来

个人预测分计算结束后，先剔除硬排除伤病球员，再分别尝试两种阵型：

- 2 名前场 + 3 名后场；
- 3 名前场 + 2 名后场。

每种阵型使用动态规划，逐名处理球员，并记录“选了多少前场、多少后场、消耗多少能量”时能够得到的最高预测分组合。能量状态从 0 到 150，因此任何超过上限的组合都不会被记录。

每种阵型完成后，取五人预测分总和最高的合法组合；再比较两种阵型的结果，返回总分更高的一组。结果中的预计总分是入选五名球员 `projected` 的和，能量是其 `energy` 的和。

### 这不等于“必须耗尽能量”

BAO5 规则是能量不超过 150。当前优化目标只有预测总分，没有“尽量用满能量”的奖励，也没有把剩余能量转换成额外价值。若更高分球员组合刚好接近 150，结果会自然用满；如果最佳球员组合只花 130，模型也会保留 20 能量。

当前算法也没有“最多用 135 能量”或多目标探索模式。若要比较节能策略，需另行设置能量预算并同时输出两套方案；不能把尚未实施的实验当作当前推荐行为。

### 同分时

动态规划只在新组合分数严格更高时替换已有状态；相同能量、相同预测分的组合通常保留先遍历到的那组。候选池来自 BAO5 球员列表的原始顺序，因此完全同分时结果可能受数据源列表顺序影响。目前没有显式的球员 ID 或能量偏好作为第二排序规则。

## 6. 推荐分与“价值”字段

球员列表中的 `projected` 是按上述公式计算并保留一位小数的单人预测分。`value` 定义为：

```text
value = projected / max(1, energy)
```

价值主要用于候选池排序和观察性比较。当前阵容优化目标不是最大化每能量得分，而是最大化五人的预计总分；能量只作为硬上限。

## 7. 数据刷新、缓存与提交边界

- 页面初次打开会请求仪表盘；页面显示期间会每 5 分钟刷新一次（页面处于后台时跳过定时刷新）。
- 刷新接口重新登录并读取球员/赛程等动态数据；服务端会缓存已生成的 dashboard，强制刷新时重新构建。
- 当日榜单本地快照若已有结算排名和榜单数据，会直接复用；否则新快照 10 分钟内复用。更早的数据会触发重新抓取，失败时回退到磁盘快照。
- 前五阵容只有日榜名次达到前五且阵容已公开时才可学习；未公开不代表空阵容。
- 推荐展示不会自动提交。单日提交/未来七天同步由独立 API 操作触发，并按锁定时间和 BAO5 接口结果校验。

## 8. 赛后如何形成反馈

1. 预测时保存日期、球员 ID、预期总分、能量和阵型等信息。
2. 结算后优先读取 BAO5 日榜的本人实际分数和排名；自动任务可用 NBA 官方 Box Score 作为备用来源。
3. 写入实际分、排名、预测误差 `实际分 − 预测分` 和结果来源。
4. 前五阵容公开后保存阵容成员及逐人分数，累计成前五偏好统计。
5. 后续预测使用新的总体校准系数与前五偏好。

这属于“数据回填 + 总体校准 + 低权重人气/表现反馈”，不是自动训练全新的预测模型。系统不会仅凭某天输赢自行推导并永久改写全部信号权重。

## 9. 一份虚构计算示例

以下数字只用于说明流程，不代表真实球员或实际结果。

假设球员 A：

- 基础换算分 30；出场 10 场，可信度系数为 `0.5 + 0.5 × 10/20 = 0.75`，基础预测为 22.5；
- 有近期均值 26，近期权重 18%；历史信号缺失；近期混合后为 `22.5 × 82% + 26 × 18% = 23.13`；
- 对位系数 1.02，盘口系数 1.01；
- 官方伤病未限制，无伤病条目，伤病系数 1；无替补机会，替补系数 1；
- 前五偏好系数 1.01；季前赛阶段系数 0.84；校准系数 1.03。

于是：

```text
最终预测 ≈ 23.13 × 1.02 × 1.01 × 1 × 1 × 1.01 × 0.84 × 1.03
        ≈ 20.5 分
```

算法对每个候选人重复同样过程，然后在符合位置与能量约束的五人组合里取总预测分最高者。界面显示的一位小数可能与上面中间步骤略有出入，因为内部完整值用于乘法，显示时才四舍五入到一位小数。

## 10. 已知限制与解读建议

- BAO5 场均数据未必代表当日上场时间；当前模型没有可信的预计分钟、首发概率和实时使用率模型。
- 季前赛轮换折扣是统一常数，不会因球员年龄、教练或季前赛场次自动变化。
- 位置对位及历史对阵的数据来源、样本量和统计口径有限，适合轻量修正，不应当作强证据。
- 伤病硬排除规则依赖状态键/文字；新状态词如果未加入规则，可能只会走概率默认值。
- 总体校准把不同阶段、不同球员、不同数据质量的样本合并，不能指出误差来自哪一项信号。
- 前五偏好可能引入赢家偏差：公开的前五阵容是少量高排名样本，不代表稳定因果规律，所以权重应保持低并持续回测。
- 预测分不是得分保证。页面理由可以帮助追溯主要信号，但不等同于完整概率解释。

## 11. 不读代码时，建议如何复盘一名球员

按此顺序查看仪表盘里的球员理由与候选表：

1. **基础分**：场均统计换算出的分数是否合理，出场样本是否很少？
2. **近期与历史**：数据是否实际存在？若不存在就不会发挥作用。
3. **对手与赔率**：是否有匹配数据？缺失时应按中性理解。
4. **健康**：伤病来自官方还是聚合来源？是否触发硬排除？
5. **机会/人气**：加成是否来自同位置队友缺阵或已公开前五样本？
6. **阶段/校准**：是否季前赛折扣？总体校准系数是多少？
7. **阵容层**：该球员是否因 150 能量或前后场名额被组合优化器排除？个人分高并不保证一定入选。
