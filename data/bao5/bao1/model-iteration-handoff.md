## 这个系统做什么

系统在每个比赛日前，按球员分别预测 BAO5 Fantasy 得分，并利用五项信号、预计上场时间、伤病和队友缺阵造成的轮换变化来修正预测。阵容推荐只是下游应用；复盘的核心对象是有比赛球员的逐人预测与实际得分，不以当天最终选中的五人为样本边界。

五项可调信号是近期状态、历史对阵、位置对位、赔率和前五选人热度。预测应使用当时保存的输入快照，不能让赛后数据泄漏进预测。主要位置取预测时保存的位置分布中占比最高的位置；五个位置 C、PF、SF、SG、PG 要分开评估。

## 每次复盘的底线

- 用最新一周已结算比赛的球员预测/实际分逐人配对；尽量用预测时保存的位置、对位、预计分钟、伤病和模型分项快照。发现记录缺失时先追查 API 或回填链路，不要把缺失当成 0 分。
- 按比赛时间先用较早日期评估候选调整，再用较新的日期留出验证。报告样本数、MAE、RMSE、Bias，并分列 C、PF、SF、SG、PG；如果样本不足或留出误差未稳定改善，保留当前参数。
- CV 保护至少比较 15%、20%、25% 阈值及实际误差、样本量和触发人数。不能因某个明星最近均分高就直接把预测设成近六场均分；仍要保留五项信号和预计分钟，只做有留出证据的小幅修正。
- 逐球员检查近期、历史对阵、位置对位、盘口和选人五个信号与误差的关系；个性化权重至少需要近 28 天 8 条有效已结算预测，并向当前全局权重收缩，小幅、一次改一项、按较新日期留出验证。样本不足就只记观察，不拟合。
- 对位权重依据预测时主要位置与对位快照分位置评估；区分试验组与同期对照，不能把 C/PF 结论外推到全部位置。
- 每次结束都在 `model-iteration-log.md` 末尾追加记录：数据范围/覆盖、基线与候选指标、位置误差、CV 阈值对照、实际参数变化或保留原因、回退办法、链路状态和下一次观察点。并更新本 Handoff 的“当前模型状态”。
- 只做可解释的小幅本地模型迭代。不要自动提交 BAO5 阵容，不要推送代码到远端；整理改动供本对话复核。
